# Email Deliverability and Compliance

## Provider

Kutuzov Studio uses Resend server-side. `RESEND_API_KEY` and `STUDIO_EMAIL_FROM` are deployment secrets and must never be exposed to browser code or committed to Git.

## Domain authentication

Before production sending, authenticate the sender domain in Resend and publish the provider's DNS records. SPF and DKIM are sender-authentication controls. DMARC defines how recipient systems should treat messages that fail authentication and provides reporting. The exact DNS values are generated by Resend for the selected sending domain and must be copied from the provider dashboard rather than hard-coded in this repository.

## Application controls

The Studio email route applies origin checks, request-size limits, attachment size and MIME limits, recipient validation, HTML escaping, rate limiting, retry handling and an idempotency key for provider retries.

Resend supports idempotency keys for the `/emails` API. The Studio endpoint uses a request-scoped key so a transient retry does not intentionally create a duplicate send.

## Operational controls

Production operations should monitor the Resend delivery dashboard for bounces, complaints, failures and unusual volume. Repeated hard bounces should be suppressed rather than repeatedly retried. Network/provider failures are retried only within the bounded application retry policy.

## Data protection

Only the minimum recipient and business-card information required for the email should be sent. Retention, deletion, lawful basis, consent/opt-out requirements and cross-border processing obligations must be reviewed for the jurisdictions in which the service operates. This repository documents engineering controls; legal review remains an operational requirement.

## Acceptance checklist

- Sender domain verified in Resend.
- SPF published correctly for the chosen sending domain.
- DKIM records published and passing.
- DMARC policy published and monitored.
- Resend bounce/complaint monitoring enabled.
- Production secret stored only in the deployment secret manager.
- Test sends verified in at least one Gmail and one Outlook mailbox.
- Mobile rendering checked on a current iPhone and Android device.
